# Power Up

A Bun + TypeScript + ECSpresso platformer with a gameplay sandbox and a separate primitive test screen. Both use the same amber platform and cyan player. No external artwork.

```sh
bun install --frozen-lockfile
bun run dev
```

Open the URL printed by Bun (normally http://localhost:3000). Click the browser page if keyboard focus is elsewhere. For LAN access, use `bun run dev --hostname=0.0.0.0`.

- Touch: start anywhere on the left half of the play area to anchor a floating joystick; drag horizontally for proportional movement. Use the right-hand **Jump** and **Attack** buttons simultaneously with movement. Release to stop; hold Attack for contact, and release/repress Jump for another grounded jump or the air jump earned by a connected third strike. Controls appear on touch-capable devices in both screens and fullscreen. Rotation, focus loss, cancellation, and screen changes clear held touch input.
- Move: **A / D**, **Left / Right**, gamepad **left stick** or **D-pad**.
- Attack fixture: hold **J** or gamepad **button 2** (standard left face button). Faces the last movement direction.
- Jump: **Space** or the gamepad **primary face button** (standard button 0).
- Jump requires a fresh press and either ground contact or the single air jump earned when the third melee strike connects. The earned jump lasts until used, landing, or fall reset; it ends any current lunge and its gravity tail. Other airborne presses are discarded; holding jump does not repeat it.
- Falling below the world returns the player to the middle of the platform with velocity and force reset. Held movement resumes on the next tick.

Use **Fullscreen** in the top-right of the play area to expand the canvas; **Exit fullscreen** returns to the page. The button has a 44px minimum touch target and respects display safe areas. When [native fullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) is unavailable or rejected, the play area fills the browser viewport (browser chrome may remain). Escape also closes this fallback. Both screens retain the same logical view and letterboxing as the canvas resizes, including on rotation. Touch controls stay inside the expanded play area.

```sh
bun run typecheck  # TypeScript
bun test           # deterministic ECS/input/physics scenarios
bun run build      # production output in dist/
bun run preview    # serve the production output at http://localhost:3000
bun run check      # all three
```

Development uses Bun's native HTML server with automatic bundling and reloads. Production uses `Bun.build()` with `index.html` as the entry point, minification, and external source maps. Preview uses `Bun.serve()` to serve the built files directly; set `PORT` to choose another preview port. This follows Math Marsh's native Bun approach without its project-specific packaging or asset plugins.

TypeScript enables `strict` and all additional type-checking diagnostics: exact optional properties, checked indexed access, index-signature access restrictions, explicit overrides, complete returns, switch fallthrough checks, unused declarations, unreachable code, and unused labels. Side-effect imports, import casing, and isolated module transpilation are checked too. These apply to `src`, `tests`, and `scripts`. `skipLibCheck` remains enabled because Pixi's installed bitmap-font declaration fails exact optional-property checking. Dependency declarations are skipped; application code and its use of dependency APIs remain checked.

`src/main.ts` composes the browser application and owns startup, graphics, focus cleanup, page teardown, and Bun hot-reload disposal. ECSpresso's managed `renderer2D` owns Pixi and its ticker; the world owns input listeners. `src/game.ts` composes transform, input, physics, and a small gameplay plugin. Tests use the same simulation without a renderer.

Simulation runs at 60 Hz with explicit ordering: input → player control → physics integration → collision resolution → fall reset → transform propagation → combat detection. Gravity, motion, restitution-free collisions, transforms, grounded state, and reset all live in ECS components/systems. Physics collision normals establish ground contact after the built-in solver removes penetration and downward velocity. Input is sampled in `fixedUpdate` so jump edges survive render frames with no simulation tick and are consumed once across multiple ticks.

`src/view.ts` defines the 960×540 logical viewport separately from `LEVEL_BOUNDS` in `src/game.ts`. Fall reset still occurs at level bottom 540 plus player height, regardless of camera position or visible dimensions. ECSpresso's camera plugin stores the view center; renderer2D's `camera: true` applies it to the scene, and `screenScale: { mode: 'fit' }` provides uniform scaling and centered letterboxing. A Pixi mask clips world graphics to the logical viewport, including when panning into letterboxed areas. No custom renderer, collision solver, or game loop is needed. One small input integration fix releases tracked keyboard keys on window blur because the installed input plugin does not clear them itself.

The isolated `src/camera-review.ts` adapter adds temporary review buttons below the game: **Pan left/right** shifts the view by 160 world units, **Pan up/down** by 90, and **Reset view** restores the initial view. Press Pan right twice to reveal the violet marker at world (1120, 270). The marker has no entity, collider, or simulation effect; this does not expand the playable level. These controls do not establish future gameplay bindings. Camera follow, smoothing, shake, zoom controls, and aiming are deferred.

`src/coordinates.ts` exports `worldToScreen` and `screenToWorld`. Their camera argument is the world coordinate at the viewport's **top-left**, obtained by subtracting half the viewport size from ECSpresso's camera center. Screen points use browser **client CSS pixels**, matching `PointerEvent.clientX/clientY`; pass the canvas's current `getBoundingClientRect()` so page position, scrolling, canvas scaling, and centered letterboxing are included. The current adapter uses translation with fixed zoom 1 and rotation 0. Conversions extrapolate within letterbox margins rather than clamping and reject invalid/nonpositive geometry with `RangeError`. The review pointer draws a white ring in world space and shows its world/client coordinates; letterbox points map outside the view and the ring is clipped.

Dependencies are pinned in `package.json` and `bun.lock`: ECSpresso **0.24.1**, Pixi **8.22.0**. Integration was checked against the installed package exports, declarations, implementation, changelog, and the matching [v0.24.1 platformer example](https://github.com/DeeGeeGames/ecspresso/blob/v0.24.1/examples/platformer/platformer.ts) and [plugin documentation](https://github.com/DeeGeeGames/ecspresso/blob/v0.24.1/docs/built-in-plugins.md).

## Gameplay sandbox

The app opens on **Gameplay**. **Test screen** retains the stationary combat targets, projectile/beam fixtures, and camera review controls. Switching screens starts a fresh level and resets the camera; **Restart sandbox** clears the current gameplay run and its spawn timer. ECSpresso screens own navigation and screen-scoped level entities; presentation adapters release their graphics, subscriptions, ticker callbacks and controls before switching.

One basic ground enemy spawns immediately on the first simulation tick, then every two seconds from alternating platform ends, up to eight live enemies. They walk at 90 world units/second toward the player's horizontal position and stop beside the player without overshooting. Physics keeps them on the platform; horizontal pursuit clamps their bodies inside its edges even when the player leaves the platform. They never jump or fly, and keep chasing horizontally while the player is airborne. Existing movement, jump, gamepad and fall-reset behavior is shared between screens.

Ground enemies have solid rectangular colliders (pushboxes) that block one another during pursuit and melee knockback. Movement reserves free space before physics integration so crowds cannot compress into overlapping bodies or push one another beyond the platform edges. An occupied spawn location delays that side until a later spawn interval has room. Child hurtboxes remain separate from these physical boxes; enemies turn gold during melee hit stun, and a translucent gold rectangle shows the active player attack. There is no health, damage, enemy attack, or player/enemy body blocking yet. Restarting provides a fresh pursuit setup after the population reaches its cap. `GROUND_ENEMY` in `src/game.ts` holds speed, spawn interval and population limit; spawn/chase systems run only on Gameplay. `src/ground-enemy-view.ts` draws current simulation state without separate movement or spawn timers.

`tests/ground-enemies.test.ts` covers spawn cadence and alternating sides, measured pursuit, stopping and reversing, grounded behavior under an airborne target, both platform edges, population bounds/replacement, and repeated screen/restart cleanup including child combat volumes. `bun run check` passes all 41 tests, typechecking and the production build. Production-browser checks at 1280×800/900 and 390×844 observed movement/jump with grounded pursuers, contact feedback, restart, screen switching, the preserved projectile fixture's three ordered contacts, one canvas after switching, and no horizontal page overflow. Portrait uses desktop browser emulation; physical controller/mobile behavior and owner acceptance of feel remain unmeasured.

## Combat overlap primitive

`src/combat.ts` provides `createCombatVolume(ownerId, kind, width, height, x, y, active)` and the `combat` plugin. Spawn the returned components with `world.spawnChild(ownerId, ...)`. Each attack/hurtbox is an independent entity with a `combatVolume`, transform, AABB collider, and attack/hurtbox collision layer; it has **no rigid body**. Owner movement colliders remain separate. Installed ECSpresso 0.24.1's detection-only collision plugin handles overlap tests; its physics solver only queries rigid bodies, so these volumes cannot resolve physical collisions. No new dependency or custom detector is needed.

Set `combatVolume.active` to enable/disable either volume; use `removeEntity(volumeId)` to remove it. Default owner removal cascades to its children. Contact forwarding also validates both owners exist, including non-cascading owner removal. Removing a volume's `combatVolume` component stops combat forwarding. No previous-contact cache is retained by the primitive.

`combatContact` is a synchronous, transient event with `{ attackId, ownerId, hurtboxId, targetId }`, once per overlapping attack/hurtbox pair on **every fixed simulation tick**, including sustained overlaps. There are no enter/exit events, deduplication across ticks, or contacts on frames with zero fixed ticks. Multiple fixed ticks in one render frame each report contacts. `combatScan` marks the start of each detection pass for presentation consumers. Consumers retaining events own their history and must revalidate identities before later use. The review adapter clears its display per scan and checks activation/existence again before drawing.

Geometry is the library's smallest supported primitive: world-axis AABBs with positive width and height. Edge touching does not count as overlap. Parent hierarchy translation, rotation, and scale affect the attached **center**; the installed detector keeps dimensions and collider offsets in world units, without rotating or scaling the box. Debug outlines draw these same world-space rectangles inside the existing camera root and viewport mask. They can be toggled without affecting detection. Detection samples after physics and reset on each tick; swept/continuous projectile collision is deferred.

The fixture places one enemy in reach of the initial right-facing attack and two farther away. Targets remain still until struck and have no health, damage or AI. Tap J for one complete swing, tap during a swing/recovery to buffer one follow-up, or hold J (gamepad button 2 / touch Attack) to repeat a three-hit chain. Each strike is active for 0.12s, followed by 0.14s recovery (0.28s after the finisher); 0.45s idle resets the chain. Facing is locked during each swing, with movement restored during recovery. Swings only lunge when they acquire a target; untargeted swings preserve normal horizontal movement. Magnetism selects the nearest active enemy hurtbox within 110 units in any direction (360-degree coverage), angling the lunge and hitbox upward/downward toward that target and boosting travel up to about 35 units while shortening it near a target to avoid passing through it. Vertical assistance is a single impulse added to existing jump/fall momentum, with gravity suppressed during a targeted lunge and for a quarter-second tail afterward. Untargeted swings do not suppress gravity or renew that tail. Aim is locked for each swing and reacquired on the next strike; without a valid target, the hitbox stays horizontal and no lunge is applied. Diagonal hitboxes use an enclosing AABB for broad-phase detection and the same oriented rectangle intersection as beams for precise contacts. Each swing turns to face its target; a directly vertical target preserves horizontal facing. Targets beyond 110 units or at the exact same position do not attract the player. Every enemy in the hitbox receives one hit per swing: 0.24s stun and decaying pushback at 150 units/s, increased to 0.38s and 230 units/s for the third strike. Stun suspends pursuit, pushback stays within the platform edges, and pursuit resumes afterward. Fall reset clears the combo and hitbox immediately. Generic projectile, beam and contact reporting remain unchanged; only the player melee hitbox applies this response. Tuning and state live in `src/melee.ts`; application systems live in `src/game.ts`. Uncheck **Show combat outlines** to hide only the debug overlay.

`tests/combat.test.ts` covers strict overlap, activation of both kinds, identity, consecutive/multiple/zero fixed ticks, parent transform propagation, volume/component/owner removal (including non-cascading removal), unchanged motion of two overlapping dynamic bodies, and keyboard/gamepad fixture activation/facing/reset. Existing movement and camera tests remain in place.

## Swept projectile primitive

`src/projectile.ts` adds `createProjectile(ownerId, position, velocity, width, height, lifetime)` and the `projectiles` plugin. Spawn it as an independent **root** entity with `world.spawn(...)`, not as an owner's child. It carries the same `combatVolume` attack identity and AABB as melee, explicit world position in its root transform, velocity in world units/second, and remaining lifetime in seconds. It has no rigid body or collision layer: gravity, physical resolution, and duplicate endpoint contacts do not apply. Owner removal or removal of the attack identity/collider removes the shot on its next fixed tick. Parenting projectiles is rejected.

Movement runs in `fixedUpdate` before transform propagation. Sweeping runs after transform propagation and endpoint collision detection. Each live tick checks the complete straight-line path against active hurtbox AABBs with live owners, plus static rigid-body AABBs as solid obstacles. Hurtbox centers include hierarchy transforms and collider offsets, with the same unscaled, world-axis dimensions as ECSpresso collision. Projectile boxes are centered, axis-aligned and unrotated. Dynamic/kinematic solids, circles, moving-target continuous collision, projectile parenting/rotation/scale, and changing projectile collider offsets are outside this primitive's supported geometry. Targets are sampled at their current propagated position, without reconstructing their motion during the tick.

The sweep expands each target by the projectile's half extents and intersects the movement segment with that box. Positive overlap is required, matching #2: edge/corner tangency alone and an endpoint that only reaches an edge are misses; starting positive overlap reports fraction zero, including a stationary shot. Contact `fraction` is the entry boundary along the **live portion** of the tick, and `position` is the projectile center there. Lifetime age derives from integer fixed-tick counts, with a relative floating-point boundary clamp to prevent decimal durations leaving a stale contact tick. The final tick is clipped to remaining lifetime, then the entity and children are removed through ECS commands before rendering. Off-screen position never triggers removal.

`projectileSweep` publishes one snapshot per live shot per fixed tick with `attackId`, `ownerId`, `from`, `to`, and an ordered `contacts` array. A target contact extends the existing `CombatContact` identity with `kind: 'target'`, `fraction`, and `position`; a solid contact uses `kind: 'solid'` and `obstacleId`. Sort order is ascending fraction, then **solid before target for exact ties**, then ascending collider entity ID. This avoids query-order-dependent results. Target contacts also publish the original unchanged `combatContact` payload in this order, reusing the shared activation/identity validation. These generic target events precede `projectileSweep`; future stop/pierce/impact rules must consume the complete ordered sweep rather than infer an impact policy from each generic overlap event. Events describe that fixed tick, not a retained active-contact cache. Each shot is independent; there is no global time ordering across shots. Starting overlaps can report again on later ticks, leaving damage cadence to future rules.

The primitive reports all contacts along the live path and continues moving. It chooses no damage, team filtering, stop, piercing, or ricochet policy; passing through the fixture's amber wall demonstrates reporting only. Future impact rules can use the ordered sweep result. Beam/area attacks use the separate sustained lifecycle described below.

`src/projectile-fixture.ts` provides a renderer-free configurable fixture; `src/projectile-review.ts` adds its temporary browser controls below combat review. **Launch projectile** starts at world (240, 200); defaults are 24,000 units/s, an 8×8 projectile, and 0.35 seconds lifetime. The first 60 Hz tick goes to x=640, completely crossing two 4-unit-wide rose targets at x=380 and x=500 and an amber static AABB at x=620. The contact log reports center x=374, 494, and 612 in order. Adjust speed/lifetime, select **Near miss** to pass above every obstacle, or **Clear projectile** for explicit removal. Cyan bodies and translucent swept trails are drawn only for live shots and cleared each render. The lane, targets and wall are static fixture guides; the explicitly labeled **Last run** text is historical evidence and persists after expiration. No per-shot graphics, subscriptions, timers, or contact caches are retained. Pan the camera while a slower/longer-lived shot travels to inspect world alignment.

Installed ECSpresso 0.24.1 declarations and implementation were inspected: collision exports endpoint AABB/circle detection, without swept/raycast queries. Its combat projectile plugin provides linear/homing movement and endpoint collision with automatic removal (and optional damage), without swept-volume detection or finite lifetime. Neither satisfies this primitive. A small slab query reuses the installed collider, transform, event, and command APIs; no general collision engine or additional dependency is introduced.

`tests/projectile.test.ts` covers thin-target crossings, extent-sensitive hits and misses, starting/stationary overlap, edge entry/departure, diagonal/reverse/vertical travel, offsets, stable contact ordering, fractional-lifetime clipping, zero/multiple fixed ticks, disposal callbacks/children, identity removal/activation, camera independence, and the exact browser fixture. Existing player and melee scenarios remain in the suite.

## Sustained beam / area primitive

`src/beam.ts` exports `createBeam(ownerId, from, to, width, active = true)` and the `beams` plugin. Spawn a beam as a **root** entity. Its `beam` component stores explicit world-space endpoints and a positive finite width; endpoints must be distinct. Geometry is a flat-ended oriented rectangle, without rounded caps. Set `combatVolume.active` to activate/deactivate and mutate `beam.from`, `beam.to`, or `beam.width` to aim, move, or resize while active. A stationary rectangle is an area attack. There is no automatic expiration: sustained coverage persists until deactivation/removal, independent of camera and viewport. Pulses, extension/retraction, damage and repeat-hit policy are deferred by owner decision.

The existing `combatVolume` owner/attack identity and `getCombatContact` activation checks are shared with melee/projectiles. There is no rigid body, collider or endpoint collision layer on the beam. Removing its owner, attack identity, or changing the identity away from attack removes the beam and children on the next fixed tick. Explicit entity removal is immediate; removing the `beam` component stops processing/rendering. Parenting is rejected. Invalid active geometry throws `RangeError`; callers must keep edits valid and mark component changes through ECS APIs.

Each active fixed tick, after transform propagation and collision detection, publishes `beamScan` with `{ attackId, ownerId, geometry, contacts }`. Geometry is copied for that scan. Target contacts include the shared `CombatContact` identities plus `kind: 'target'` and `fraction`; solid contacts use `kind: 'solid'`, `attackId`, `ownerId`, `obstacleId`, and `fraction`. `fraction` is the nearest longitudinal coverage position from start (0) to end (1), including zero for starting overlap. Contacts sort ascending by fraction, solid first for exact ties, then ascending collider ID. **All contacts through solids report**, with no clipping or occlusion. Each target also publishes the unchanged `combatContact` payload before `beamScan`. Consumers own any history and must revalidate identities before later use. No enter/stay/exit cache, cross-tick deduplication, or global ordering across beams exists. Inactive beams and zero-fixed-tick frames publish nothing.

Supported targets are active hurtbox AABBs with live owners; solids are static rigid-body AABBs. Centers include propagated hierarchy transforms and collider offsets, with unscaled world-axis dimensions matching the projectile/combat primitives. Targets and beam geometry are sampled at the current tick; moving targets and moving/rotating beams are not swept between ticks. Strict positive area overlap is required: edge/corner-only contact misses. Dynamic/kinematic solids and circles are outside this contract. Installed ECSpresso 0.24.1 collision/combat declarations provide no oriented beam-volume query. The projectile slab helper sweeps a world-axis body, so reusing it for an oriented rectangle would overstate diagonal coverage. A small strict separating-axis check and convex rectangle clip handle this bounded geometry without a new collision engine or dependency; shared combat integration is reused directly.

`src/beam-fixture.ts` supplies renderer-free fixture setup; `src/beam-review.ts` adds temporary controls for activation, start X/Y, angle, length, width, and explicit removal/recreation. Defaults cover two thin rose targets with an amber solid between them; the log reports target → solid → target, and targets turn gold while covered. Changes take effect immediately, and deactivation works even with invalid geometry input. Pan right to inspect the same world geometry. Static guides remain visible while inactive; active coverage and contact text clear. The single graphics object, ticker callback, event subscriptions, DOM listeners, beam, and fixture entities are released on teardown.

`tests/beam.test.ts` covers width-sensitive hits/misses, strict ends/edges, starting overlap, diagonal/reverse/vertical geometry, invalid inputs, deterministic pass-through ordering, zero/multiple ticks, deactivation/reactivation, live geometry changes, target offsets, volume/component/owner removal, camera/off-screen independence, and the exact browser fixture. `bun run check` passes 37 tests plus typechecking and production build. Production-browser checks at 1280×1400 and 390×844 observed full coverage through the solid, live reconfiguration to a miss, camera panning, explicit removal/recreation, invalid-input deactivation, and unchanged projectile fixture contacts. Portrait is desktop browser emulation; physical device/controller acceptance remains unmeasured.

## Melee hit stop

Confirmed melee damage pauses gameplay for 50 ms (three fixed ticks), or 80 ms on
strike three (rounded up to five ticks, about 83 ms). Misses do not pause. Hits on
several enemies use the longest requested pause rather than adding durations.
The impact tick completes so damage and death appear immediately; subsequent
paused ticks hold physics, combo/recovery, stun/pushback, enemy spawning,
projectiles, and beam scans. Paused time is consumed without a catch-up burst.
Input and rendering continue, with sampled attack/jump taps buffered until play
resumes. Screen switches and sandbox restarts clear the pause. Explicit external
damage events still complete their synchronous health/death cleanup.

Defaults live in `src/melee.ts`; `src/hit-stop.ts` owns the fixed-tick gate.
`tests/hit-stop.test.ts` covers duration, multi-target hits, frozen gameplay,
continued rendering, buffered input, misses, screen resets, and external death.
